## 2. 问题与优化目的

### 当前有什么问题

- **触发场景：** 什么数据、配置或运行阶段下出现问题？
- **基线证据：** 指标、耗时分解、显存统计或可视化，说明问题确实存在。
- **影响：** 问题对重建质量、速度、显存或稳定性有什么影响？

### 本次希望达到什么目标

- **主要目标：** 明确要改善的指标和方向。
- **成功标准：** 实验开始前填写可判定的阈值，例如“峰值显存降低至少 X%”。
- **约束指标：** 可接受的质量损失、时间开销或其他代价，例如“PSNR 下降不超过 Y dB”。
- **适用范围：** 希望在哪些场景有效？本次实际验证哪些场景？

## 3. 优化方案与假设

- **改了什么：** 修改的模块、文件、关键参数及前后行为。
- **为什么这样改：** 预期机制，用“改动 → 中间变化 → 指标变化”描述。
- **可验证的预测：** 如果机制成立，应该观察到什么现象？
- **可能的代价：** 是否可能降低质量、增加耗时或影响其他场景？

## 5. 实验结果

> 按场景及重复实验保留原始结果，再汇总；只有一次运行时注明，不声称结果具有统计稳定性。按需增删指标。

| 场景 / 汇总范围 | 指标 | 基线 | 优化后 | 变化 | 是否达到预设标准 |
|---|---|---:|---:|---|---|
|  | 测试集 PSNR ↑ |  |  | dB 差值 |  |
|  | 测试集 SSIM ↑ |  |  | 绝对差值 |  |
|  | 测试集 LPIPS ↓ |  |  | 绝对差值 |  |
|  | 训练耗时 ↓ |  |  | 百分比 |  |
|  | 峰值显存 ↓ |  |  | 百分比 |  |
|  | 渲染 FPS ↑ |  |  | 百分比 |  |

- **计算口径：** 差值 = 优化后 − 基线；百分比变化 = (优化后 − 基线) / 基线 × 100%。正负是否代表改善取决于指标方向；基线为零时不计算百分比。
- **重复实验汇总：** 样本数、均值和标准差；说明是跨种子还是跨场景汇总。场景较少时逐个展示，避免平均值掩盖退化。
- **可视化对比：** 使用相同场景、帧、视角，标出改善与退化区域。
- **效果视频：** 提供真值、固定基线和本次结果的视频链接，记录数据时刻、相机顺序、帧数、分辨率和播放 FPS；沿用 BASELINE-001 的导出规则，按同一数据时刻对齐。新视角还须固定相机轨迹。
- **异常与失败：** 记录 OOM、崩溃、不收敛等情况，以及是否排除及原因。
- **原始记录：** 日志、逐次运行指标、对比图及配置快照的位置。

## 6. 是否有效，原因是什么

### 是否有效

对照第 2 节逐项判断：主要目标是否达到？约束指标是否满足？效果是否稳定？是否只对部分场景有效？

**结论：** 有效 / 无效 / 退化 / 证据不足。填写结论及适用范围。

### 为什么有效或无效

| 机制解释 | 支持证据 | 其他可能解释 / 尚缺验证 |
|---|---|---|
| 例如：减少某阶段的中间张量驻留，降低峰值显存 | 对应阶段的显存分析、张量规模统计，以及关闭该改动后的对照 | 随机波动、训练质量下降或其他同时变化的参数是否能解释结果？ |

**机制验证：** 按需增加消融实验、性能剖析或参数扫描。指标改善本身不能证明机制；未验证的原因写为“推测”，并列出后续验证方法。
